Bài toán & kiến trúc

Cho bug report (ngôn ngữ tự nhiên) + mã nguồn → tìm file/method chứa lỗi, xếp hạng. Thách thức: report mơ hồ; lỗi thường không ở file được nhắc mà lan truyền qua chuỗi gọi hàm.

Bug Report → Comprehension (sinh giả thuyết) → PriorityNavigation (khám phá heap) → Confirmation (xác nhận + xếp hạng) → UnifiedScorer (10 tín hiệu) → ListwiseRerank → Ranked files

Triết lý thiết kế: tách phần xác định (Python, reproducible) khỏi phần hiểu (LLM, đắt). Cấu hình chuẩn: E1+E2+E3 bật; Patch Duel (H1) & RRF consensus tắt.

3 đóng góp phương pháp (bật/tắt độc lập → ablation nghiêm ngặt)

  • E1 — Vòng lặp giả thuyết cạnh tranh: sinh K=4 hypothesis, belief-tracking log-odds thuần Python; LLM chỉ gắn nhãn bằng chứng.
  • E2 — Khám phá ưu tiên: heap scheduler tách khỏi LLM (chỉ chấm điểm); context O(1)/bước, không tích lũy token.
  • E3 — Listwise rerank: thu hẹp file→function, hoán vị top-K, permutation-only (recall bất biến), fail-open.
  • Code Property Graph: AST + quan hệ gọi/kế thừa/import; anchor matching + BFS → định vị file không được nhắc.

Claim cốt lõi (paired McNemar, n=300): +14 điểm Top-1 (59 thắng / 17 thua), p = 1.4 × 10⁻⁶ — ý nghĩa rất mạnh. Top-5 không ý nghĩa (p=0.28): bare-LLM đã "nhớ" repo phổ biến. Top-1 ngang SOTA dù backbone qwen-plus yếu hơn Claude/GPT-OSS.
Ablation (n=50, 6 thí nghiệm): mọi cố gắng nén vòng lặp agent (single-shot, hybrid) đều giảm Top-1 5–10đ dù Top-3/5 giữ. ⇒ Vòng lặp agent = cơ chế chuyên biệt cho Top-1, không thay bằng single-pass.  |  Negative result: RRF + Patch Duel NULL trên n=300 (−1.7đ, p=0.55) → giữ tắt.

Hạn chế & kết luận

Threats: memorization benchmark public (bare = cận trên suy luận); 300 inst đầu chưa random; đơn model qwen-plus. Headroom: tầng recall (+10đ), phân định tầng liền kề (+7đ, 21 case rank-2).
Kết luận: Hệ đa tác tử + RAG + CPG tạo ra giá trị định vị thực sự, có ý nghĩa thống kê mạnh so với bare-LLM; vòng lặp agent là cơ chế không thể nén cho Top-1 discrimination.
